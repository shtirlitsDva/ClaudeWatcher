# Task: Wire HTTP server to SessionManager to ViewModel to Cards

<description>

Connect the HTTP server endpoints to the UI layer so that incoming hook events create, update, and remove session cards in real time. This is the integration task that makes the app functional end-to-end.

**Data flow:**
```
Claude Hook → HTTP POST → HookServer endpoint
  → SessionManager.RegisterSession/UpdateSession/etc.
    → SessionManager raises event (SessionAdded/Updated/Removed)
      → MainViewModel handles event on UI thread
        → Adds/updates/removes SessionCardViewModel in ObservableCollection
          → WPF data binding updates the card UI
```

**MainViewModel integration:**
- Subscribe to `SessionManager.SessionAdded`, `SessionUpdated`, `SessionRemoved` events
- On `SessionAdded`: create a new `SessionCardViewModel`, populate from `SessionInfo`, add to `Sessions` collection. Show window if it was hidden.
- On `SessionUpdated`: find existing `SessionCardViewModel` by `SessionId`, call `UpdateFrom(SessionInfo)` to refresh properties (status, message, context %)
- On `SessionRemoved`: find and remove `SessionCardViewModel` from `Sessions`. Hide window if collection is now empty.
- All event handlers must marshal to UI thread: `Application.Current.Dispatcher.InvokeAsync()`

**Status mapping from hook events:**
- `SessionStart` → status = `Working`
- `Stop` hook with `stop_hook_active = false` → status = `Idle` (Claude finished, no more work)
- `Stop` hook with `stop_hook_active = true` → status = `Working` (Claude will continue)
- `Notification` with `notification_type = "permission_prompt"` → status = `Waiting`
- `Notification` with `notification_type = "idle_prompt"` → status = `Waiting`
- Any `StopFailure` or error notification → status = `Error`

**Message extraction:**
- From `Stop` hook: extract `last_assistant_message`, truncate to first 200 characters, set as card message
- If no message available, keep the previous message

**Context usage extraction:**
- From `Stop` hook: read `used_percentage` and `context_window_size`
- Pass to `SessionCardViewModel.UpdateContextBar()`

**Title derivation:**
- On `SessionStart`: derive default title from `cwd` using `GitInfoHelper`
  - Extract folder name from path
  - Run `git -C <cwd> branch --show-current` to get branch
  - Detect worktree via `git rev-parse --git-dir` vs `--git-common-dir`
  - Format: "FolderName - branch" or "FolderName - parentBranch - worktreeName"
- Title can be overridden by future update calls

**Orphan detection timer:**
- `DispatcherTimer` running every 60 seconds
- If a session's `LastUpdatedUtc` is >5 minutes old and status is `Working`, set status to `Waiting` with message "Session may be stalled"
- If >30 minutes old, remove the session card

**App startup wiring (`App.xaml.cs`):**
1. Create `SessionManager` singleton
2. Create and start `HookServer` (passing `SessionManager`)
3. Create `MainViewModel` (passing `SessionManager`)
4. Create `MainWindow` with `DataContext = MainViewModel`
5. Don't show window yet (hidden until first session)

</description>

```bash
# Register a session
curl -X POST http://127.0.0.1:22322/api/session/start \
  -H "Content-Type: application/json" \
  -d '{"session_id":"test1","cwd":"C:/projects/myapp","model":"claude-opus-4-6"}'

# Update it
curl -X POST http://127.0.0.1:22322/api/session/update \
  -H "Content-Type: application/json" \
  -d '{"session_id":"test1","last_assistant_message":"Reading file src/main.ts","used_percentage":35,"context_window_size":200000}'

# Send notification
curl -X POST http://127.0.0.1:22322/api/session/notification \
  -H "Content-Type: application/json" \
  -d '{"session_id":"test1","notification_type":"permission_prompt","message":"Needs permission for Bash"}'

# End it
curl -X POST http://127.0.0.1:22322/api/session/end \
  -H "Content-Type: application/json" \
  -d '{"session_id":"test1"}'
```
