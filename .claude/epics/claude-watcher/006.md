# Task: Terminal tab focus via UI Automation and process tree fallback

<description>

Implement the card click handler that brings the correct terminal window and tab to the foreground. This is the most technically challenging task in the project due to undocumented Windows Terminal internals.

**TerminalFocusService (`Services/TerminalFocusService.cs`):**

**Primary strategy — UI Automation tab title matching:**
1. The SessionStart hook sets the tab title to `CW:{session_id_short}` via OSC escape sequence
2. When user clicks a card, the service receives the expected tab title
3. Enumerate all Windows Terminal windows by class name `CASCADIA_HOSTING_WINDOW_CLASS` using `AutomationElement.RootElement.FindAll()`
4. For each WT window, search descendants for an element whose `Name` property matches the title
5. Try `SelectionItemPattern.Select()` on the matching element to switch to that tab
6. Fall back to `InvokePattern.Invoke()` if SelectionItemPattern is not supported
7. Get the WT window's `NativeWindowHandle` and call `SetForegroundWindow()` + `ShowWindow(SW_RESTORE)`

**Focus-stealing prevention workaround:**
Windows blocks `SetForegroundWindow()` calls from background processes. Workaround:
```csharp
[DllImport("user32.dll")] static extern bool AttachThreadInput(uint idAttach, uint idAttachTo, bool fAttach);
[DllImport("user32.dll")] static extern IntPtr GetForegroundWindow();
[DllImport("user32.dll")] static extern uint GetWindowThreadProcessId(IntPtr hWnd, out uint processId);
[DllImport("kernel32.dll")] static extern uint GetCurrentThreadId();

void ForceForeground(IntPtr hwnd)
{
    uint foreThread = GetWindowThreadProcessId(GetForegroundWindow(), out _);
    uint appThread = GetCurrentThreadId();
    if (foreThread != appThread)
    {
        AttachThreadInput(foreThread, appThread, true);
        SetForegroundWindow(hwnd);
        AttachThreadInput(foreThread, appThread, false);
    }
    else
    {
        SetForegroundWindow(hwnd);
    }
}
```

**Fallback strategy — process tree walking:**
If no WT window with matching tab title is found (session started in a non-WT terminal), fall back to:
1. Use `ProcessTreeHelper` to walk from the session's shell PID up the process tree
2. Find the first ancestor process that has a visible main window
3. Call `SetForegroundWindow()` + `ShowWindow(SW_RESTORE)` on that window

**ProcessTreeHelper (`Helpers/ProcessTreeHelper.cs`):**
- `GetParentProcessId(int pid)` — uses `CreateToolhelp32Snapshot` + `Process32First`/`Process32Next` P/Invoke
- `FindTerminalWindow(int shellPid)` — walks up the process tree until finding a process with a non-zero `MainWindowHandle`

**UI Automation element discovery:**
The exact `ControlType` of Windows Terminal tabs is undocumented and version-dependent. Strategy:
1. First try `ControlType.TabItem`
2. If no matches, try `ControlType.ListItem`
3. If still no matches, try searching by `Name` property only (any ControlType)
4. Log which ControlType worked for debugging

**Tab title matching:**
- Primary: exact match `CW:{short_id}`
- Secondary: if the OSC escape didn't work (title not set), try matching by the default title which includes the working directory path

**Error handling:**
- If UI Automation throws (WT window closed between enumeration and access), catch and skip
- If no matching tab found, show a subtle tooltip on the card: "Could not find terminal tab"
- Never crash the app on focus failure

</description>
